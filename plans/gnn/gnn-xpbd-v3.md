## 结论

**有，而且优化方向不是继续扩大 GNN，而是重构 GNN 与 XPBD 的耦合方式。**

你当前的主线可以概括为：

```text
GNN 预测完整一帧位移/加速度
        ↓
Verlet 一次性跳到 x_gnn
        ↓
在同一个大时间步内做 128 次 Jacobi XPBD 后投影
```

这个方向已经证明“混合优于纯 GNN”是成立的，但具体结构仍然是**网络负责制造状态，XPBD 负责事后抢救**。仓库自己的结果已经非常清楚：混合架构能救回普通战斗动作，却会在高惯性 root-motion 中产生巨大瞬时超冲；而且 `edge_p95` 看起来最好时，布料反而可能拥有最多的塌陷边、最小的三角形面积和最多的翻面。换句话说，当前瓶颈不是模型容量，而是**时间积分、约束表达、接触更新以及网络输出的权威性过高**。

我最推荐的下一代结构是：

# **Soft-Guided Multirate XPBD**

### GNN 只提供“软引导形状”，XPBD 成为真正的时间积分器和稳定性所有者

------

## 一、当前架构为什么会出现超冲和压瘪

### 1. GNN 输出被当作不可质疑的完整下一帧状态

`hood_integrate.comp` 当前直接执行：

```hlsl
predicted =
    effective
    + (effective - previous)
    + acceleration;
```

随后才进入 XPBD。也就是说，网络输出并不是一个受约束的力、软目标或低频引导，而是直接决定整个时间步的预测位置。

当动作位于训练分布内时，这种结构很高效；但在 `sprint_start` 这样的高二阶根运动中，GNN 可以一次把顶点送到距离可行域很远的位置，然后 XPBD 只能从这个坏初值开始做局部投影。

你测到的曲线正好符合这一机制：

| 分支    | step 30 | step 60    | step 90   | step 120  |
| ------- | ------- | ---------- | --------- | --------- |
| 纯 GNN  | 2.480   | 5.253      | 7.368     | 9.472     |
| 纯 XPBD | 3.178   | 2.491      | 2.952     | 2.754     |
| 混合    | 8.220   | **10.364** | **1.219** | **1.287** |

混合分支不是永久发散，而是**运动期间被一次性预测推得过远，动作停止后又被约束拉回**。因此这更像积分和耦合问题，而不是模型完全不会该动作。

------

### 2. 128 次大时间步投影，不等价于 128 个小时间步

当前 XPBD 的全部迭代都发生在一个 `dt=1/30` 的预测之后，第一步甚至使用 `dt=1/3` 的特殊 settle 步；每个模拟步开始时 λ 清零，然后在同一个预测状态附近连续线性化和投影。

而 Small Steps 的核心结论就是：在相同约束求解次数下，

```text
1 个大时间步 × N 次迭代
```

通常明显差于：

```text
N 个小时间步 × 每步 1 次迭代
```

因为小时间步会反复更新惯性预测、约束梯度、碰撞状态和速度，而不是围绕同一个已经很差的预测点持续投影。([数字图书馆](https://diglib.eg.org/items/322424d5-a24f-490a-a6bb-542233852032))

这项改动很可能是你当前**收益最高、且不需要重新训练网络**的实验。

------

### 3. 当前约束只能阻止拉长，无法阻止压扁

当前 Vulkan XPBD 的结构约束只有：

- 网格边距离约束；
- 跨相邻三角形的“两跳距离”弯曲约束；
- 可选的 one-sided 模式，只处理 `distance > target`；
- 每个顶点一个最近身体代理平面。

所谓 bend 目前并不是真正的二面角约束，而是相邻三角形两个对角顶点之间的距离约束。

one-sided stretch 的结果是：

```text
边太长 → XPBD 修
边太短 → 完全合法
三角形面积趋近 0 → 只要没有边太长，也可能合法
三角形被压到身体表面 → edge_p95 甚至会变得更好
```

这正是 `sprint_start` 末态中发生的事情：混合分支 `edge_p95=1.291` 最好，但同时有 **13.3% 塌陷边、三角面积中位数 0.478、翻面率 0.435**，视觉上裙子被压成贴在髋部的一小片。

因此 S9 不应该只做一个额外距离约束，而应该转向：

1. 三角形材料应变约束；
2. 三角面积下限或退化 barrier；
3. 真正的二面角弯曲约束。

Strain-Based Dynamics 的做法是直接约束三角形 Green–St Venant 应变张量，从而把经纬向拉伸和剪切分离，不再依赖网格边方向。([数字图书馆](https://diglib.eg.org/items/cc63570f-a032-410b-9d71-cebca83a936c))

------

### 4. 碰撞约束在整次 XPBD 求解中是“过期”的

`hood_world_nearest.comp` 在 GNN/XPBD 之前为每个布料顶点选择一个最近身体代理；随后所有 XPBD 迭代都复用这个代理索引和对应平面。

这意味着：

- 顶点被大幅移动后，最近身体表面可能已经变了；
- 在两腿、腋下、裙摆内侧等区域，一个最近切平面往往不够；
- 没有 swept collision，顶点可能直接跨过表面；
- 没有摩擦；
- 没有自碰撞。

所以即使增加到 256 或 512 次 XPBD 迭代，也只是在更准确地求解一个**已经过期的局部半平面约束**。仓库也已经记录最近代理判据对隧穿会失明，并且当前完全没有自碰撞。

------

### 5. 网络输入没有显式保证伽利略不变性

当前节点特征包含：

```text
current - previous
proxyTarget - proxyPosition
```

这些都是世界空间中的绝对速度型量；网络输出也位于世界坐标系。

这会导致一个理论上不应发生的差异：

```text
完全相同的局部人物动作
├── 原地动画
└── 带世界 root-motion 的动画
```

物理上，匀速平移本身不应改变布料相对人物的运动；真正产生惯性的是根节点的线加速度、角速度和角加速度。但当前网络需要自行从大量世界空间速度中“学会抵消”刚体运动。

这很可能是 23 条原地 locomotion 和两条高速 root-motion 出现明显分裂的一个架构原因，而不是简单的数据量不足。

------

## 二、推荐结构：把 GNN 输出改成软目标，而不是硬初值

建议把当前：

```text
x = x_gnn
XPBD_Project(x)
```

改成：

```text
x̃ = 物理惯性预测

GNN → x_guide + confidence

求解：
    惯性项
  + 物理结构约束
  + 碰撞约束
  + 软 GNN 引导项
```

对应的优化形式可以写成：

# [ x_{n+1}

\arg\min_x
\frac{1}{2h^2}\Vert x-\tilde{x}\Vert_M^2
+
E_{\text{strain}}(x)
+
E_{\text{bend}}(x)
+
E_{\text{contact}}(x)
+
\sum_i \frac{k_i}{2}\Vert x_i-x_i^{guide}\Vert^2
]

其中：

- (\tilde{x})：普通惯性预测；
- (x^{guide})：GNN 给出的期望形状；
- (k_i)：网络置信度决定的引导强度；
- 物理约束永远拥有最终否决权。

在 XPBD 中，可以把 GNN 引导实现成每顶点三个软位置约束：

[
C_i(x)=x_i-x_i^{guide}
]

网络置信度映射到 compliance：

```text
高置信度 → compliance 小 → 更接近 GNN 形状
低置信度 → compliance 大 → 退化为纯 XPBD
```

这个结构有三个关键优势。

### 第一，存在明确的稳定退化路径

```text
confidence = 0  → 纯 XPBD
confidence 较低 → XPBD 为主，GNN 轻微塑形
confidence 较高 → 接近当前混合效果
```

当前结构没有这条连续路径：网络预测要么全部保留，要么全部丢弃。

### 第二，不会丢掉 GNN 的约束零空间分量

仓库已经实测：把网络位移投影成结构约束 λ 的 warm start，效果几乎等同于直接丢掉网络位移，因为 (J^T\lambda) 无法表示刚体平移和其他不改变边长的形变。

软 guide 约束的 Jacobian 是单位阵 (I)，所以它能保留：

- 整体裙摆摆动；
- 低频褶皱位置；
- 不改变边长的形状变化；
- GNN 所贡献的“正确外形”。

因此它与已经失败的 λ warm start 是本质不同的。

### 第三，可以在网络出错时局部降权

可以先不训练 confidence，直接使用解析门控：

```text
confidence ↓ 当：
- GNN 位移超过局部最短边的一定比例；
- 预测后出现严重面积压缩；
- 预测后穿模深度过大；
- 根节点二阶运动超出训练范围；
- 网络预测后的约束残差突然升高。
```

你的 `.vxpbd` 资产里已经 bake 了 `min_edge`，但当前 kernel 尚未使用，因此 trust region 的资产基础已经存在。

------

## 三、完整的推荐运行流程

```text
上一物理帧最终投影状态 xₙ, vₙ
          │
          ├─ 转换到角色 root-local 坐标系
          │
          └─ GNN 每个视觉帧只运行一次
                 输出：
                 1. guide displacement / guide pose
                 2. confidence
                 3. 可选的局部阻尼参数
                          │
                          ▼
             将视觉帧拆成 N 个物理子步
                          │
        ┌─────────────────┴─────────────────┐
        │ 每个子步：                        │
        │ 1. 插值骨骼、pin 和碰撞代理       │
        │ 2. 计算惯性预测 x̃                │
        │ 3. 插值 GNN guide target          │
        │ 4. 重新查询身体接触               │
        │ 5. 求解 guide 软约束              │
        │ 6. 求解应变、面积、二面角约束     │
        │ 7. 求解碰撞与摩擦                 │
        │ 8. 从最终位置更新速度             │
        └───────────────────────────────────┘
                          │
                          ▼
             最终投影状态反馈给下一帧 GNN
```

GNN 不需要每个子步都运行。它仍然可以保持当前约 `0.924 ms` 的每视觉帧成本；只需对子步内的 guide target 做插值或把网络输出解释为持续一帧的引导力。

------

## 四、最值得立即做的等预算实验

先不要训练新模型，也不要立刻做自碰撞。使用完全相同的 GNN 权重和相同的总 XPBD sweep 数量，测试：

| 配置       | 子步数 | 每子步迭代 | 总迭代 | GNN 使用方式 |
| ---------- | ------ | ---------- | ------ | ------------ |
| A 当前基线 | 1      | 128        | 128    | 硬初值       |
| B          | 1      | 128        | 128    | 软 guide     |
| C          | 2      | 64         | 128    | 软 guide     |
| D          | **4**  | **32**     | 128    | 软 guide     |
| E          | 8      | 16         | 128    | 软 guide     |

每个子步都需要：

- 插值身体代理和 pin target；
- 更新惯性状态；
- 至少重新执行一次最近身体查询；
- 使用 (h=dt/N) 重新计算 XPBD compliance；
- 更新子步速度。

**最关键的是：不能先完整跳到 `x_gnn`，然后只把 XPBD 拆成子步。** 那样初始超冲仍然已经发生。应当把 GNN guide 逐子步施加，或者将其解释为加速度并按 (h^2) 缩放。

优先测试这些动作：

```text
sprint_start
sprint_start_180
sprint_unarmed
dodge_left
sprint_skirt
guard_skirt
block_loop_skirt
```

同时交叉测试 `student32x12_v3` 与 `r1`。现有结果中，r1 虽然是最好的裸 GNN，却是最差的 XPBD 搭档；v3 在混合 T-pose 上反而最好，因此不应继续默认 r1 是混合架构的最佳权重。

## 五、结构约束应当怎样升级

### 第一阶段：快速验证面积退化是否是主要原因

先增加单边面积下限：

[
C_A(x)=\max(\rho A_0-A(x),0)
]

初始可以扫描：

```text
ρ = 0.2 / 0.3 / 0.4 / 0.5
```

它只阻止三角形趋近零面积，不要求三角形维持固定朝向，因此不会直接禁止正常折叠。

### 第二阶段：使用材料空间应变约束替代纯边长体系

每个三角形根据 UV 或 rest tangent 构造：

[
F=D_sD_m^{-1}, \qquad G=F^TF
]

分别求解：

```text
G00 - 1   经向拉伸
G11 - 1   纬向拉伸
G01       剪切
```

这样可以：

- 使用不同的 warp/weft stiffness；
- 防止不真实的面内压缩和剪切；
- 降低网格方向对结果的影响；
- 避免依赖大量两点距离约束。

### 第三阶段：真正的二面角弯曲

将当前 two-hop distance bend 改成：

[
C_b=\theta-\theta_0
]

面积/应变负责面内稳定，二面角负责面外弯曲，职责会比现在清晰很多。

------

## 六、网络特征应改成 root-local、显式惯性形式

推荐把所有布料和身体状态转换到角色 root 或 pelvis 局部空间。

相对速度使用：

# [ v_i^{rel}

R^T
\left[
v_i-v_{root}-\omega_{root}\times(x_i-p_{root})
\right]
]

并额外输入：

```text
root linear acceleration
root angular velocity
root angular acceleration
gravity in root-local frame
当前 dt
```

这样：

- 匀速世界位移自然被消去；
- 高速起跑真正有影响的二阶运动被显式暴露；
- 原地动画和 root-motion 动画不再形成完全不同的输入分布；
- 世界 yaw 变化不会要求网络重新学习一遍方向语义。

输出也在 root-local 或三角形材料局部坐标系中预测，最后再旋回世界空间。

此外，当前 decoder 输出虽名为 acceleration，但实际上被直接作为 Verlet 位移项加入。长期最好将输出契约改成真正的物理加速度：

[
x_{n+1}=x_n+h v_n+h^2a_{\text{gnn}}
]

并在训练中随机化 (h)。否则模型只会记住 `1/30` 和特殊的 `1/3` 两个时间尺度，无法自然支持 substep。

------

## 七、去掉特殊的 1/3 秒首帧 settle

训练代码已经记录，首帧 `dt=1/3` 的目标能量约为稳态步的 **28.8 倍**，它长期主导了单步损失和网络选择。

更合理的结构是将初始化与运行时动力学分开：

```text
加载/重置：
静止身体
→ 30～60 个小 XPBD 子步
→ 逐渐提高 guide strength
→ 得到无穿模初始 drape
→ v = 0
→ 正常 1/30 或 1/60 模拟
```

动画跳切、传送和 LOD 切换也应进入专门的 recovery/reset 模式，而不是把巨大位移交给普通 GNN 时间步处理。

------

## 八、训练和模型选择也必须围绕混合闭环重写

当前训练虽然加载了多个场景，但模型选择路径仍主要使用 `ch10032_tpose` 的裸学生 rollout；这与 r1 的过拟合现象是一致的。

新的选择目标应当是：

```text
GNN
→ soft guide
→ substepped XPBD
→ 最终物理状态
→ 计算 loss
```

数据至少按以下类别平衡：

- 静态 drape；
- 战斗裙摆；
- 原地 locomotion；
- 带 root-motion 的起跑/停止；
- 0.5×～3× 播放速度；
- 随机折叠、穿入、拉伸扰动；
- 动画切换和 root warp。

选择分数不建议继续取所有动作平均，而应使用：

```text
硬安全门槛
→ 最坏动作
→ CVaR / 最差 10%
→ 最后才是平均视觉误差
```

否则四个完全崩溃的动作很容易被大量简单动作的平均分掩盖。

训练穿过 XPBD 在技术上是可行的，DiffXPBD 已给出高自由度、含碰撞的可微 XPBD 形式；但结合你当前“梯度训练提高单步保真却破坏闭环稳定”的实测，我不建议第一步就反传 128 次投影。应先用固定权重验证新耦合，再做短展开、混合闭环选型，最后才尝试可微 fine-tune。([arXiv](https://arxiv.org/abs/2301.01396))

------

## 九、性能方面应为 substep 腾预算，而不是继续压缩网络深度

当前 XPBD 每轮约 `9.44 µs` 的主要原因是 occupancy：1377 个顶点只有 11 个 workgroup。仓库预计把执行形状改成“一个 workgroup 处理一个或多个顶点、lane 并行处理 incident slots”后，可将 k=128 从约 `1.21 ms` 降到接近 `0.37 ms`，但这是尚待实测的外推。

这里我会稍微修改仓库当前的 kernel 设想：

```text
不要固定 128 lanes 只处理 1 个顶点的 18 个 slot
```

可以优先测试：

```text
128-thread workgroup
= 4 个逻辑子组
× 每个顶点 32 lanes
```

CH10032 的 slot width 是 18，32 lanes 已经足够覆盖一个顶点，还可以把 workgroup 数提高到约 345，同时减少 128-lane reduction 的浪费。使用 groupshared 固定顺序归约即可保持 AMD/NVIDIA 通用性和确定性，不依赖 float atomic。

这部分节省出的预算，应该优先用于：

1. 4 个子步；
2. 面积/应变约束；
3. 每子步接触刷新；

而不是再砍 GNN block。仓库已经证明 64×4 比 32×12 更慢且更容易发散，宽度昂贵、深度相对便宜。

------

## 十、长期终态：学习型 V-Cycle，但预测 primal correction，不要只预测 λ

在上述结构稳定之后，可以进一步改成：

```text
惯性预测
→ 1～2 次 XPBD pre-smooth
→ 构建结构与接触残差
→ 将残差限制到 coarse graph
→ GNN 预测 coarse primal correction + confidence
→ prolongate 到细网格
→ trust-region clamp
→ 1～3 次 XPBD post-smooth
```

HOOD 使用层级图的原始动机正是快速传播布料中的长程刚性拉伸模式。([arXiv](https://arxiv.org/abs/2212.07242))

不过在你的混合架构里，XPBD 已经承担了长程结构稳定，因此 GNN 更适合：

- 预测低频形状；
- 预测 coarse correction；
- 恢复合理 drape；
- 作为预条件器加速收敛；

而不是继续独自预测完整动力学。

要特别避免只输出结构 λ：仓库现有 warm-start 实验已经说明，它无法表达 (J^T) 零空间中的有用形状位移。应输出 coarse **primal displacement**，随后再由 XPBD 投影。

------

## 最终优先级

我建议按这个顺序推进：

1. **修正指标**：补上 edge 下尾、area 下尾、退化率、穿模深度、峰值和恢复时间。
2. **等预算 Small Steps**：`1×128 / 2×64 / 4×32 / 8×16`。
3. **把 GNN 硬初值改成带 compliance 的软 guide**。
4. **加入面积下限，随后升级为应变 + 真二面角约束**。
5. **每子步插值身体并刷新接触**。
6. **完成 XPBD occupancy 改造，为子步腾预算**。
7. **root-local/Galilean-invariant 特征与 confidence head**。
8. **用混合闭环而非裸 GNN 指标训练和选型**。
9. **swept body collision、摩擦和自碰撞**。
10. **最后再做 learned V-cycle 或替换 GNN 前驱**。

其中最关键的三项是：

> **软 GNN 引导 + 4×32 小步长 XPBD + 三角形面积/应变约束。**

这三项分别对应当前三个最明显的失败源：**高惯性超冲、单大步收敛不足、布料压瘪**。在它们验证之前，继续扩大 GNN、继续搜索裸模型稳定性或单纯增加 Jacobi 次数，预计都不会从根本上改善结果。
