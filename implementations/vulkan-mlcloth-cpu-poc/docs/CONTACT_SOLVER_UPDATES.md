# 接触求解与混合引导进展

开发状态，尚未达到七动作质量验收目标；实时性能测试按用户安排后移。

## STM 接触方向和首次碰撞

最近点落在网格边或顶点时，单个三角形的面法线不一定给出正确的内外方向。CPU 和 Vulkan 改为角度加权顶点伪法线、相邻面合成边伪法线，并沿最近点分离方向计算有符号距离。扫掠接触在实际命中时刻重新计算局部伪法线，不能直接用最终姿态法线替代。

扫掠选择先比较命中时间，再用距离和三角形编号处理平局。落点靠近薄身体的另一侧时，不再用较晚的出口面替代首次入口接触。凸边、凸顶点和薄体高速穿越均有独立预期位置测试及 CPU/GPU 对照。

伪法线方法参考 [Bærentzen 与 Aanæs 的角度加权伪法线论文](https://www2.imm.dtu.dk/pubdb/edoc/imm3578.pdf)。它不能修复代理本身的开口、自相交或蒙皮错误。

## 接触感知的粗层引导

UI 的 `Contact-aware ML guidance` 控制混合分支。每个子步在积分之后，从当前身体姿态生成接触平面；STM 使用最近表面与伪法线，胶囊和地面使用解析距离。近接触带宽为 `max(4 × thickness, 12 mm)`。每次结构迭代之后，根据质量加权的片区质心差计算实际引导方向；当它朝附近碰撞体内部吸引时，降低该粗层片区的引导强度。不能用单个顶点的 ML 偏差代替整个粗层约束的方向。离开表面、沿表面移动或关闭身体碰撞时不降低强度。

片区取参与顶点的最低置信度，保持整个片区的质心约束，不逐顶点覆盖网络预测。该标量会一起减弱片区三个方向的引导，复杂多面接触中仍可能过于保守。置信度每子步重新生成，不进入检查点、纯 ML 显示或网络 PCA 历史；纯 XPBD 不读取该缓冲或 ML 输出。CPU 与 Vulkan 对地面、STM、胶囊分别验证朝内、朝外和切向目标。

## 自碰撞归约和容量回退

接触修正原先按原子追加次序做浮点求和。追加次序受 GPU 调度影响，舍入差异会在连续模拟中放大。常规 gather 改为以该顶点最大修正分量缩放的整数累加，每分量不超过 2²¹，最多 256 项，总和在有符号 32 位范围内。平均修正的量化误差上界约为最大修正分量的 1/2²²；无需排序或浮点原子操作。

超过 256 条接触时，从完整接触记录按固定源编号重新 gather，避免只保留随机先到的接触。大三角形/边桶超过 512 项时，停止向桶外写入，并让查询回退到完整 BVH。正常播放的记录和求解数据仍驻留 GPU。

目前合成 GPU 检查 88 项通过，包含 300 条接触的 gather 溢出、重复求解精确一致、513 个大三角形的桶溢出，以及局部预测向内但质心目标向外的情况；CPU 34 项测试通过，完整网格三种单步对照和显示插值检查通过。完整 5,294 顶点网格在静止身体下恢复检查点、重放 48 个含身体/自碰撞的子步，位置误差为零。这些测试不能替代真实资产长时间稳定性验证。

## 资源候选和独立测量

默认继续使用已独立验证的 1,719 顶点上身/臀部 STM 加 10 节腿部胶囊。另生成 5,482 顶点 STM 候选，独立姿态中手臂/臀部表面距离有所缩小，但动作快照没有一致改善，因此未替换默认资源。

`measure_demo_snapshot.py` 保留旧的最近面平面深度，同时增加三方向有向射线的独立内外分类和最近表面欧氏距离。身体原网格存在开口/相交片，报告明确记录不一致射线数量；这些点不能按“无穿透”处理。代理与身体分别统计，不把代理零穿透等同于身体零穿透。

`validate_demo_collision_candidate.ps1 -ContactGuide 0/1` 生成同动作终态、截图和几何报告。`compare_demo_collision_runs.py` 检查同一可执行文件、资源清单及采样时刻，并要求纯 ML、纯 XPBD 两个对照分支完全相同；否则不能把差异归因于混合引导开关。所有这些报告均为 `qualification: false`。
