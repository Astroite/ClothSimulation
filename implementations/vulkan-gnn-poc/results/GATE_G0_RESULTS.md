# 门禁 G0 实测结果：GNN + XPBD 混合是否值得做

执行 [`plans/gnn/gnn-xpbd-v2.md`](../../../plans/gnn/gnn-xpbd-v2.md) 的门禁 G0。全部在 Python 闭环里跑完，
未改动任何 Vulkan 代码。测试机 RTX 4060 Ti，torch 2.10.0+cu128。

## 结论

**混合架构在全部四个场景上都胜过两个单独分支，且最好的配置是最便宜的那个（无色 Jacobi，
估计 +0.36 ms）。但我预先写死的 G0-a 判据在 2/4 场景上触发了，需要如实说明。**

最佳配置（jacobi k=128 + `teacher` 标定 + one-sided）跨场景，2 次重复，score 越低越好：

| 场景 | A：GNN only | B：XPBD only | **C：混合** | C 相对 A | 噪声 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `hml_001962`（137 帧运动） | 0.7356 | 2.4123 | **0.4049** | −45% | 0.007 |
| `ch10032_tpose`（静态） | 0.2412 | 2.2539 | **0.2174** | −10% | 0.000 |
| `ch10032_sprint`（62 帧快速运动） | 2.5297 | 2.1723 | **0.6065** | **−76%** | 0.050 |
| `hood_grid64`（合成压力场景） | 1.8770 | 1.6950 | **0.1591** | **−92%** | 0.118 |

**最重要的模式：混合架构的收益在学生最差的场景上最大。** `ch10032_tpose`（r1 被调优的那个场景）
上学生已经很好（0.241），混合只提升 10%；而在 `ch10032_sprint` 和 `hood_grid64` 上学生崩到
2.53 / 1.88，混合把它们拉到 0.61 / 0.16。

这正好对上 `STUDENT_STABILITY_ROUND2.md` 记录的核心遗留问题 —— r1 是靠"直接搜索闭环指标"拿到的，
代价是**过拟合被打分的那个场景**。实测说明 **XPBD 补的恰恰是学生泛化不了的部分**。

### 关于 G0-a 判据的如实说明

我预先写死的判据是"若 B 的最佳 score ≤ A，则砍掉 GNN"。在 `ch10032_sprint`（2.17 < 2.53）和
`hood_grid64`（1.70 < 1.88）上它**确实触发了**。

但"砍掉 GNN"这个动作并不成立，原因是判据本身有缺陷：**它假设了"若 XPBD-only 不比 GNN-only 差，
则网络无用"，而网络完全可以只在组合中有用。** 在这两个场景上 C 比 B 好 3.6 倍和 10.7 倍。
正确的读法是三方对比，结论无歧义：**C ≪ min(A, B)，四个场景都是。**

真正被这两个场景证伪的不是"网络有用"，而是"r1 学生在训练场景之外可靠"。B 支在四个场景上
稳定在 1.70–2.41，而 A 支从 0.24 摆到 2.53 —— **学生的方差比 XPBD 大得多**。

### 三个与 v2 方案预期相反、需要改方案的发现

1. **v2 推荐的方案 B/C 方向（预测 λ / 约束空间 warm start）实测拿不到任何好处** ——
   三个场景上"投影到约束空间"与"干脆丢掉网络预测"差 ≤ 0.03，因为网络位移有一部分在 Jᵀ 的
   零空间里，λ 参数化按构造表达不了。
2. **不应该做图着色。** 实测色数 18（v2 §2.3 估计 16–20，估对了），但因为成本是 dispatch
   受限的，无色 Jacobi 用 1 dispatch/迭代换 18，在**等成本**下质量明显更好。
   v2 把 Jacobi 写成"退路"，实测它是正确默认。
3. **`cloth_rest` 不能作为约束目标**，这一条在动手前就必须处理，否则实验会静默失效。

## 一、必须先处理的事：`cloth_rest` 不是一个可用的约束目标

`tools/audit_rest_lengths.py` 实测各场景**蒙皮 frame 0** 的边长 / authored rest 边长：

| 场景 | 帧数 | p95 | max | >1.5 | >3 | >6 | rest 可用 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| `hml_001962` | 137 | 1.081 | 5.27 | 86 (2.2%) | 27 | 0 | 否 |
| `ch10032_tpose` | 1 | 1.890 | 12.11 | 305 (7.7%) | 69 | 17 | 否 |
| `ch10032_sprint` | 62 | 2.025 | 16.31 | 323 (8.2%) | 111 | 79 | 否 |
| `hood_grid64` | 1 | **1.000** | 1.00 | 0 | 0 | 0 | **是** |

只有合成的 grid64 自洽。真实服装上，光是蒙皮就把 2.2–8.2% 的边拉长到 1.5× 以上。用 `cloth_rest`
边长做距离约束会把这些边往回缩最多 12–16 倍，把服装撕成另一个方向的错。
`tools/train_student.py` 的 `edge_penalty` 文档串已经记录过这个教训的训练侧版本。

所以约束目标改为参数（`bind` = 蒙皮 frame 0，`teacher` = teacher rollout 中位数，`rest` = 对照）。
三者都扫过，`teacher` 最好（见第五之二节）。第三、四节的模式对比用 `bind`，跨场景最佳配置用 `teacher`。

### 一个关于既有指标的旁证发现

`STUDENT_STABILITY_ROUND2.md` 的全部结论在 `ch10032_tpose` 上打分，而 `edge_p95` 是对
`cloth_rest` 的比值，该场景蒙皮初态的 p95 就已经是 **1.890**。teacher 第 120 步的 1.781 是**低于**
初态的 —— 不是"teacher 把布拉长了"，而是布一开始就在 1.89、teacher 略微松弛了它。
`over`/`under` 是 teacher 相对量因此仍然有效，但绝对阈值（1.2 / 1.5 / 2.0 / 5.0）加在一个
基线为 1.89 的量上。

score 越低越好；teacher 为 0。

**噪声底**：`gate_g0_confirm.json` 用 3 次重复正式测过 —— A 支极差 **0.0141**，XPBD 各支
0.0000–0.0110（同一配置跨独立运行另见 0.7315 / 0.7187 / 0.7107，极差 0.021）。来源是
`real_scene/fine15.py:137,143` 的 `index_add_`（CUDA 上无确定性 float kernel）。XPBD 自身用
padded-gather 累加，逐位可复现，不贡献噪声。0.27 的效应量比 0.021 大 13 倍，所以本轮**不需要**
做 v2 §6.2 要求的确定性改造 —— 那道前置在 S4 训练 λ 头时才会成为瓶颈，而第四节的结果让 S4
本身变得存疑。

### 混合架构买到的是什么

`over`（比 teacher 更拉伸 = 发散）从 0.4897 降到 0.2645，edge P95@120 从 2.017 降到 1.365
（teacher 1.052），而 **A 在第 119 步越过 2.0，混合在 137 步内从未越过**。`drift` 基本不变。

也就是说 XPBD 没有让轨迹更接近 teacher，它**止住了发散**。这正是 v2 §终态给 XPBD 派的活
（"XPBD 解决 GNN 最不可靠的硬约束、碰撞和长期稳定性问题"），这一条成立。

### XPBD-only 是怎么输的（2026-08-20 修正）

B 支的 `under` ≈ 0、`over` = 1.44（k=32）。~~它不是被约束绷太硬，而是**垮掉**：没有网络提供的
动力学，重力把布往下拉、约束只限制拉伸，裙子的垂坠形状与 teacher 不同，第 4 步就越过 2.0。~~

**上面这句的机制说错了。** 四场景最终配置（k=128）的分解量是：

| 场景 | B score | **over** | under | flip | over 占比 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `ch10032_tpose` | 2.2539 | **1.9287** | 0.0000 | 0.0127 | 86% |
| `hml_001962` | 2.4123 | **1.9502** | 0.0000 | 0.0439 | 81% |
| `ch10032_sprint` | 2.1723 | **1.7832** | 0.0000 | 0.0078 | 82% |
| `hood_grid64` | 1.6950 | **0.8930** | 0.0002 | 0.0733 | 53% |

`over` 占分数的 **81–86%**（grid64 53%）。B 不是"形状与 teacher 不同"，而是**边被拉长、收不
回来** —— 一个纯粹的**收敛失败**，与垂坠形状无关。迭代数 2 → 32 的改善（3.25 → 1.75）本身
就是收敛在改善的证据。

**这个修正很重要，因为它把 B 的败因指向了我们施加给它的配置，而不是它缺少网络：**

1. **单步 128 次迭代，全仓库零 substep。** `project()` 在单个 Δt 下迭代 k 次。这正是
   Macklin 2019 *Small Steps* 指出的同预算最差用法，而 `plans/gnn/gnn-xpbd-v2.md` §8.3
   **写了"基线必须包含 small steps"却从未执行**。
2. **Jacobi。** `real_scene/xpbd.py::project` 的注释自己记着：128 次 Jacobi 只把 CH10032 拉伸
   残差降 **3.2×**。选 Jacobi 的理由是"网络挑大梁时它等成本更优"，纯 XPBD 下该前提不成立。
3. **one-sided。** 只抗拉不抗压。混合里无所谓（形状由网络给），纯 XPBD 下等于主动拿掉一半约束。
4. **只跑过一个配置。** headline 表里 B 只有 `k128_teacher_sc0_bc1e-05_onesided` 一行，
   compliance / one-sided / sweep 一次都没为 B 调过，全是从 C 的最优配置抄的。
5. **预算只有 56%。** C = GNN 0.924 + XPBD 1.208 = 2.15 ms，B = 1.21 ms。

**所以本文的 `C ≪ min(A, B)` 只证明了「混合优于本架构的消融项」，不是「混合优于纯 XPBD」。**
补正的对照是 v2 §4 的 **S10c**（substep + two-sided + 等预算）。

一并说明该补正**不影响**的部分：`fold` / `penetrate` 这类等距损伤按构造在 Jᵀ 的零空间里，
substep 改的是迭代调度而不是零空间，所以痛点导向的恢复力实验（v2 §8.0(a)）不必等 S10c
就能测。

## 四、方案 B/C 方向实测为负，但最优初始化是随场景变的

三种初始化只差一处（起点），求解器完全相同：

| 模式 | 起点 | v2 中的对应 |
| --- | --- | --- |
| `standard` | `x_gnn` | 方案 A |
| `warmstart` | `x̃ + M⁻¹Jᵀλ₀`，λ₀ 由 a 投影到约束空间 | 方案 C；也是"不训练版的方案 B" |
| `nowarm` | `x̃`，完全丢弃网络位移 | 上界对照 |

三场景实测（`bind` 标定，coloured k=32；hml 为 3 次重复的均值，来自
`gate_g0_confirm.json`，另两个场景来自 `gate_g0_breadth.json`）：

| 场景 | A（无 XPBD） | `standard` | `warmstart` | `nowarm` |
| --- | ---: | ---: | ---: | ---: |
| `hml_001962` | 0.7362 | **0.4678** | 0.8685 | 0.8670 |
| `ch10032_tpose` | **0.2417** | 0.7256 | 0.9660 | 0.9362 |
| `hood_grid64` | 2.0478 | 0.1604 | **0.1172** | **0.1173** |

**一个稳健的结论和一个不稳健的结论，分开说：**

### 稳健：`warmstart` 从来没有明显赢过 `nowarm` —— 这是方案 B 的负面结果

三个场景上两者差 ≤ 0.03（0.8685/0.8670、0.9660/0.9362、0.1172/0.1173）。也就是说
**把网络位移投影到约束空间，效果和干脆丢掉它没有区别。**

机制是结构性的：**网络的位置预测有一部分位于 Jᵀ 的零空间**（刚体平移，以及任何不改变边长的
形变），约束乘子按定义无法表达它。单元测试
`test_warmstart_discards_a_null_space_displacement` 把这一点固定下来：一个纯平移在
`warmstart` 下被投影成零，落回与 `nowarm` 逐位相同的状态。

**对方案的含义**：v1 说方案 B（预测 λ）是"更推荐的生产路线"，v2 把方案 C 提为一等变体。
**一个只输出 λ 的头，按构造无法表达网络位移中的零空间分量**，而实测这部分正是有价值的
（`hml_001962` 上 standard 0.468 对 warmstart 0.869）。

保留：`warmstart` 用的是解析对角投影，不是训练出来的 λ 头，训练可能更好。但零空间论证与训练无关。

### 不稳健：`standard` 是否最优取决于学生在该场景上有多好

- `hml_001962`（学生 0.736，尚可）：`standard` 0.468 明显最好 —— 保留网络预测有价值。
- `hood_grid64`（学生 **2.048**，崩了）：`nowarm` 0.117 好于 `standard` 0.160，
  而且 B 支（0.540）也比 A 好 4 倍 —— **学生的预测在这里是负资产，丢掉它更好。**

所以正确的说法不是"方案 A 总是最好"，而是：**网络预测该保留多少，取决于它在当前状态下
是否可信。** 这恰好是 v2 §四提出的 `confidence` 门控要解决的问题，实测支持保留那个设计
（虽然本轮没有实现它）。

### 一个必须记下的陷阱：标定选择会翻转结论的符号

`ch10032_tpose` 上用 `bind` 标定时，混合（0.7256）**比不用 XPBD 更差**（0.2417）；换成
`teacher` 标定后混合是 0.2174，**优于** A。而 `ch10032_tpose` 正是第一节测出蒙皮初态
p95 = 1.890 的那个场景 —— `bind` 在这里本身就是坏参考。

**标定不是一个小调参项，它决定混合架构在该场景上是帮忙还是拖后腿。**

## 五、不要做图着色：Jacobi 在等成本下更好

**色数实测 = 18**（3947 stretch + 3735 bend = 7682 约束；stretch-only 为 10）。v2 §2.3 估计
"stretch 10–12、合计 16–20"，**估对了**。

但成本是 dispatch 受限的（v2 §2.1：单价 ~2.8 µs，grid 路径每迭代 0.0448 ms 中的全部）。
coloured 每迭代 18 dispatch，Jacobi 每迭代 1。用 v2 附录 A 的常数换算：

| 配置 | dispatch | XPBD 估计 ms | + GNN 0.924 | score |
| --- | ---: | ---: | ---: | ---: |
| A GNN only | ~30 | 0 | **0.92** | 0.72 |
| C jacobi k=8 | 8 | 0.02 | 0.95 | 0.853 |
| C jacobi k=32 | 32 | 0.09 | 1.01 | 0.775 |
| **C jacobi k=128** | 128 | 0.36 | **1.28** | **0.532** |
| C coloured k=8 | 144 | 0.40 | 1.33 | 0.812 |
| C coloured k=32 | 576 | 1.61 | 2.54 | 0.465 |

**在约 1.3 ms 的等成本点上：jacobi k=128 得 0.532，coloured k=8 得 0.812。** Jacobi 每迭代
收敛更差（k=32 时 0.775 对 coloured 的 0.465），但 18 倍的 dispatch 优势远超这个劣势。

要 coloured k=32 的 0.465 需要 2.54 ms，是 GNN 自身成本的 2.7 倍，按 v2 §2.2 的记账等于
25 个 GNN block —— 不是一个合理的选择。

> 这里的 ms 是**用 v2 附录 A 的 dispatch 单价换算的估计，不是实测**。Python 计时无意义
> （teacher 与学生同为 16 ms/step，解释器开销主导）。真实数字仍需 S2c 在 Vulkan 上测。

## 五之二、参数扫描：one-sided 与 teacher 标定各值一大截，compliance 完全无关

在最佳成本点（jacobi k=128，`standard`）上正交扫描（`gate_g0_params.json`，A = 0.7107）：

| 标定 | 双向 | **one-sided** |
| --- | ---: | ---: |
| `bind`（蒙皮 frame 0） | 0.5244 | 0.4137 |
| **`teacher`（teacher rollout 中位数）** | 0.4086 | **0.3930** |

- **one-sided 是大赢**（只抵抗拉伸，不抵抗压缩）：0.524 → 0.414。布料本来就该在压缩时起皱而不是
  撑开，teacher 的裙子确实在折叠，双向约束会把折叠压平。
- **`teacher` 标定优于 `bind`**：0.524 → 0.409。合理 —— 被模仿的目标就是 teacher，用它自己的
  稳态边长作"未拉伸"定义最贴合。这不是运行期信息泄漏：teacher 正是蒸馏的来源，把它的稳态边长
  在 **bake 期**烘进资产是合法且免费的。
- **compliance 完全无关**：0 / 1e-7 / 1e-6 三档的 score 差 ≤ 0.002。原因是量纲 ——
  `α̃ = compliance/Δt² = 1e-6 × 900 = 9e-4`，而逆质量和约 `2/1e-4 = 2e4`，相差 7 个数量级。
  ~~**要让 compliance 起作用需要 ~1e-2 量级**~~ → **这个推断错了 3 个数量级，实测更正见第十节。**
  这是一个关于标定的观察，不是"compliance 不重要"的结论。

**最佳配置：jacobi k=128 + `teacher` 标定 + one-sided = 0.3930，对比 A 的 0.7107（−45%），
估计成本 +0.36 ms。**

## 六、预算对齐的问题仍然没有答案

最好的混合配置（jacobi k=128 + teacher 标定 + one-sided）比 A 贵约 39%（估计 1.28 对 0.92 ms）。
v2 §2.2 提出的等预算方案是砍 GNN 深度来买迭代：1 个 block = 0.0646 ms，砍 5–6 个 block 正好
腾出 0.36 ms。

**这需要重训一个 6 block 学生（`train_student.py --blocks` 支持 1–15），属于 v2 的 S4，本轮没做。**
本轮能说的是这笔交易现在有了具体赔率：**0.36 ms 的 XPBD 在四个场景上把 score 从
0.74 / 0.24 / 2.53 / 1.88 买到 0.40 / 0.22 / 0.61 / 0.16**。考虑到 12 block 的学生在
`ch10032_sprint` 上本身只有 2.53，砍一半深度换这个 XPBD 看起来划算，但必须实测。

# 第二轮：S7a 免费实验（2026-08-19）

按 `plans/gnn/gnn-xpbd-v2.md` 修订后的 S7a 跑完，**不训练任何模型**。四个结论，其中两个
更正了本文第一轮的说法。

## 八、噪声底必须跨进程测 —— 本文第一轮的噪声底被低估了 10–30 倍

第三节报的"噪声底 0.014"是**同一进程内 `--repeats` 的极差**。实测跨独立进程重跑同一配置
（r1，最佳配置，每格 4 次独立进程）：

| 场景 | A 支范围 | A 极差 | C 支范围 | C 极差 | 进程内 `--repeats` 报的极差 |
| --- | --- | ---: | --- | ---: | ---: |
| `hml_001962` | 0.7336–0.7361 | 0.0025 | 0.3989–0.4151 | 0.0162 | 0.0035 |
| `ch10032_tpose` | 0.2408–0.2411 | 0.0003 | 0.2165–0.2213 | 0.0048 | 0.0000 |
| `ch10032_sprint` | 2.5218–2.6426 | **0.1208** | 0.4657–0.6093 | **0.1436** | 0.0007 |
| `hood_grid64` | 1.7088–2.3083 | **0.5995** | 0.1590–0.1592 | 0.0002 | 0.0000 |

**机制**：同一进程内两次 rollout 背靠背执行，分配器状态与 kernel launch 配置相同，
`index_add_` 的原子累加顺序恰好复现（所以进程内极差近乎 0）；换进程后顺序变了。
**因此 `--repeats` 不是这条管线的有效噪声估计器**，`tools/refine_student.py` 的
`--eval-repeats` / `--confirm-repeats` 同样是进程内平均，它记录的"0.40 上 ±0.035"也是同一个
低估（那一轮的搜索因此可能在比噪声更小的差异上做过取舍）。

**对第一轮结论的影响**：A 对 C 的效应量是 0.3–2.2，仍远大于最大噪声 0.60，**G0 的结论不变**。
但**模型之间 0.02–0.14 量级的比较在 `sprint` / `grid64` 上不可分辨**，这决定了第九节怎么读。

顺带解释了一件事：本文第一轮记的 `sprint` C = 0.6065 与 `grid64` A = 1.8770，都落在上表区间内 ——
第一轮的**运行**没有问题，是**噪声估计**有问题。

**另一个独立结果：XPBD 不只降低 score，它还消掉了 run-to-run 方差。**
`hood_grid64` 上 A 支极差 0.5995、C 支极差 0.0002，相差 **3000 倍**。学生发散时轨迹是混沌的，
约束投影把它按回一个稳定的吸引子。

## 九、闭环搜索出来的 r1 是最差的 XPBD 搭档

仓库现有三个 32×12 权重，恰好覆盖"忠实 ↔ 稳定"这条轴，零训练成本：

| 场景 | shipped A | v3 A | r1 A | shipped C | v3 C | r1 C | 模型间极差 A → C |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| `hml_001962` | 0.9010 | 0.8979 | **0.7468** | 0.4208 | 0.4167 | **0.4035** | 0.154 → **0.017** |
| `ch10032_tpose` | 0.2874 | 0.2813 | **0.2410** | 0.2192 | **0.1988** | 0.2279 | 0.046 → 0.029 |
| `ch10032_sprint` | 2.4300 | **2.3779** | 2.5266 | 0.5119 | 0.6342 | **0.4700** | 0.149 → 0.164 |
| `hood_grid64` | 1.3559 | **0.9125** | 2.3142 | **0.1444** | **0.1444** | 0.1596 | 1.402 → **0.015** |

A 支复现了已发布值（r1 四场景 0.7468 / 0.2410 / 2.5266 / 2.3142 对第一轮的
0.7356 / 0.2412 / 2.5297 / 1.8770，全部落在第八节的区间内），所以对照可信。

在两个测得够准的场景上用 3 次独立进程复核：

| 场景 | shipped C | v3 C | r1 C |
| --- | --- | --- | --- |
| `ch10032_tpose` | 0.2186 / 0.2196 / 0.1977 | **0.1954 / 0.1881 / 0.2013** | 0.2220 / 0.2167 / 0.2171 |
| `hood_grid64` | **0.1449 / 0.1445 / 0.1448** | **0.1445 / 0.1448 / 0.1444** | 0.1590 / 0.1588 / 0.1592 |

`tpose` 上 v3 的最大值 0.2013 低于 r1 的最小值 0.2167，`grid64` 上 shipped/v3 的最大值 0.1449
低于 r1 的最小值 0.1588 —— **区间不重叠**，两处都是稳健结论。

**结论：在两个可分辨的场景上，闭环搜索过的 r1 都是三者中最差的 XPBD 搭档。**
`tpose` 上尤其干净 —— **不接 XPBD 时 r1 最好（0.2410 对 0.2874 / 0.2813），接上 XPBD 后
r1 最差（0.2186 对 0.2120 / 0.1949）。次序整个反转。**

机制正是预期的那个：那 109 分钟的搜索是靠**把学生变硬**买到稳定性的
（`STUDENT_STABILITY_ROUND2.md` 记的 `under = 0.537`），而 XPBD 也是加硬的，两者叠加过了头。

**对被推迟的训练的含义：选型目标必须是"带 XPBD 的分数"，不是裸闭环分。** 按裸分选出来的权重，
恰好是接上 XPBD 之后最差的那个。

保留：`hml` 与 `sprint` 上三者带 XPBD 后不可分辨（差值 ≤ 0.017 与 ≤ 0.164，都在噪声内），
所以"r1 最差"只在 2/4 场景上成立，另 2 个是平手 —— 没有任何场景上 r1 带 XPBD 是最好的。

## 十、compliance 到 1e-1 仍然完全无效；真实阈值在 ~15

`hml_001962`，最佳配置，8 格正交扫描（`gate_g0_compliance.json`，A = 0.7374）：

| stretch compliance | bend 1e-5 | bend 1e-2 |
| --- | ---: | ---: |
| 0 | 0.4060 | 0.4027 |
| 1e-3 | 0.4056 | 0.4060 |
| 1e-2 | 0.4032 | 0.4037 |
| 1e-1 | 0.4067 | 0.4058 |

八格全在 0.4027–0.4067，极差 0.004，**远小于该场景 C 支的跨进程噪声 0.016 —— 全部无效**。

**更正第五之二节**：那里写"要让 compliance 起作用需要 ~1e-2 量级"，**错了 3 个数量级**。
实测 `weight_sum`（逆质量和）在 `hml_001962` 上是 p5 9092 / 中位数 13816 / p95 154101，而
`α̃ = compliance/Δt² = compliance × 900`，所以

```
α̃ 追平中位 weight_sum  ⇔  compliance ≈ 13816 / 900 ≈ 15
```

| compliance | α̃ | α̃/(中位 w_sum + α̃) |
| ---: | ---: | ---: |
| 1e-2 | 9 | 0.0007 |
| 1e-1 | 90 | 0.0065 |
| 1 | 900 | 0.061 |
| **10** | 9000 | **0.39** |
| 100 | 90000 | 0.87 |

**可用区间是 compliance ∈ [1, 100]，中心约 15。** 这也说明现在的默认（compliance = 0，
完全刚性）离"有柔度"差 4 个数量级，而实测刚性已经够用 —— 所以这是一个待探索的旋钮，
不是一个待修的错误。

## 十一、标定可以跨动作迁移，而且动态动作的标定更好

`ch10032_lower.vcloth2` 被三个动作共用，但 `teacher` 标定是逐场景算的。实测（`--calibration-source`）：

| 配置 | score | 该场景自标定的区间（第八节） | 判定 |
| --- | ---: | --- | --- |
| `sprint`，用 `tpose` 的标定 | 0.5343 | 0.4657–0.6093 | **区间内，可迁移** |
| `tpose`，用 `sprint` 的标定 | **0.1936** | 0.2165–0.2213 | **比自标定更好 0.025，超出噪声** |

**两个结论：**

1. **可迁移** —— `.vxpbd` 按服装烘一份就够，不必按动作。
2. **应该用最动态的那个动作来标定。** `sprint` 的 teacher rollout 走过更宽的构型范围，它的
   中位边长比静态姿势的更能代表"未拉伸"。反方向（拿静态标定去跑动态）只是持平。

方法学说明：`--calibration-source` 指向场景自身时走的是默认路径（不额外跑一遍 teacher
rollout），JSON 里记录的 `calibration.teacher.source` 可以核对这一点。跨进程仍会因
`index_add_` 得到不同的标定，所以那个等价性只在进程内是逐位的。
